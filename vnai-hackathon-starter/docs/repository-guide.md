# Repository Guide

Tài liệu này giải thích mỗi folder dùng để làm gì trong preparation phase và implementation phase sau này.

---

## 1. Root

Root chứa tài liệu entry point và cấu hình mẫu:

```text
README.md
.env.example
docker-compose.yml
```

Hiện tại không thêm app code ở root.

---

## 2. `docs/`

Tài liệu team đọc để thống nhất cách làm.

Files quan trọng:

```text
architecture.md
api-contract.md
team-workflow.md
team-onboarding-guide.md
module-contract-template.md
ai-coding-workflow.md
mock-task-plan.md
demo-script.md
demo-safety-checklist.md
pitch-template.md
tool-stack-decision.md
preparation-roadmap.md
```

What belongs here:

* Workflow.
* API contract.
* Demo and pitch guide.
* Module contract template.
* Roadmap and onboarding.

What does not belong here:

* Real secrets.
* Random chat notes that are not cleaned up.
* Code generated by AI.

---

## 3. `ai-context/`

Tài liệu dành cho AI coding tools và người review AI-generated changes.

Files quan trọng:

```text
AGENTS.md
PROJECT_CONTEXT.md
CODING_RULES.md
MODULE_MAP.md
DECISIONS.md
PROMPT_LIBRARY.md
context-packs/
```

Rule:

* AI phải đọc file liên quan trước khi sửa code.
* Nếu module thay đổi, cập nhật context pack.
* Nếu architecture/tool decision thay đổi, cập nhật `DECISIONS.md`.

---

## 4. `ai-context/context-packs/`

Mỗi context pack là brief cho một module.

Context pack phải có:

* Purpose.
* Owner.
* Related files.
* Data flow.
* Input/output.
* API/integration contract.
* Dependencies.
* Do not rules.
* Common tasks.
* Testing checklist.
* Demo relevance.
* AI coding instruction.

Nếu file liên quan chưa tồn tại, ghi rõ `expected future file`.

---

## 5. `apps/`

Chứa runnable applications trong tương lai.

Current planned apps:

```text
apps/web
apps/api
```

Preparation rule:

* Chưa scaffold Next.js hoặc FastAPI.
* Chỉ giữ README hướng dẫn.

Implementation rule sau này:

* `apps/web` chứa Next.js frontend.
* `apps/api` chứa FastAPI backend.
* Frontend/backend giao tiếp qua `docs/api-contract.md`.

---

## 6. `packages/`

Chứa shared packages trong tương lai.

Planned packages:

```text
packages/ui
packages/prompts
packages/ai-core
packages/shared-types
packages/config
```

Rule:

* Chỉ đưa code vào packages khi thật sự dùng chung.
* Không over-engineer từ đầu.
* Không chứa secrets.

---

## 7. `data/`

Chứa data phục vụ demo và evaluation.

Folders:

```text
data/samples
data/seed
data/eval
```

Rule:

* Dùng dữ liệu mẫu ổn định.
* Không chứa dữ liệu cá nhân/thật nếu chưa được phép.
* Câu hỏi eval phải rõ expected behavior.

---

## 8. `scripts/`

Chứa utility scripts trong tương lai.

Folders:

```text
scripts/setup-dev
scripts/seed-db
scripts/run-eval
scripts/index-codebase
```

Preparation rule:

* Chưa cần script thật.
* README phải ghi rõ mục đích và rủi ro.

Implementation rule:

* Script phải an toàn.
* Script destructive phải có cảnh báo rõ.
* Không hard-code secrets.

---

## 9. `.github/`

Chứa GitHub collaboration files.

Current important file:

```text
.github/pull_request_template.md
```

PR template dùng để buộc người làm ghi:

* Module liên quan.
* API impact.
* Context pack đã đọc/cập nhật chưa.
* Demo impact.
* Risk level.
